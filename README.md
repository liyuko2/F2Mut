# F2Mut

F2Mut uses native G2FUZZ to generate seeds and initial features, then synthesizes
and expands template executors. `MutatorMin.py` loads the generated Python code
for use during AFL fuzzing.

The pipeline runs in the following order:

```text
G2FUZZ/program_gen.py
  ├─ gen_seeds/, generators/
  └─ feature_pool.json, feature_programs.json
                 ↓
template_seed_prompt_generator.py
  └─ initial executor.py
                 ↓
template_expander.py
  └─ generated_format_executors/*.py
                 ↓
MutatorMin.py loads the initial template and expanded executors
                 ↓
Normal: G2FUZZ/afl-fuzz
NoGen:  ./afl-fuzz built from this project's sources
```

Both versions share the first three generation stages. NoGen uses this project's
AFL++ loop during fuzzing and does not execute the runtime generation logic in
the G2FUZZ binary. It still uses seeds and features generated by native G2FUZZ
during preparation. The workflow invokes the native G2FUZZ CLIs directly.

## Project Structure

```text
F2Mut/
├── G2FUZZ/                         # Native generation scripts and fuzzer sources
│   ├── program_gen.py
│   ├── generator_mutation.py
│   ├── py_utils/
│   ├── src/, include/, instrumentation/
│   ├── GNUmakefile, utils/, test/, docs/ ...
│   └── LICENSE
├── run.sh                          # Entry point for the complete pipeline
├── run_pipeline.py                 # Runs native and template CLIs in order
├── run_fuzz.sh                     # Starts fuzzing with prepared artifacts
├── template_seed_prompt_generator.py
├── template_expander.py
├── MutatorMin.py
├── elf_template_executor.py
├── src/, include/, instrumentation/ # This project's AFL++ sources for NoGen
├── tests/                          # Offline CLI, executor, and launcher checks
└── runs/                           # Run artifacts, ignored by Git
```

`G2FUZZ/` provides `program_gen.py`, `generator_mutation.py`, and the fuzzer used
by the normal mode. Configuration and credential copies live in the run
directory. Both fuzzer modes load the template executors generated by this
project.

## Build

Requires a C/C++ compiler, GNU make, Python 3 development headers, and LLVM/Clang
development packages, including `llvm-config`. Native G2FUZZ invokes `python`;
make sure it resolves to the interpreter used to install the dependencies, for
example by using a virtual environment:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-mgl.txt

# This project's NoGen binary and target instrumentation tools
make -j2

# Native G2FUZZ binary and tools for the normal version
make -C G2FUZZ -j2 source-only
```

Both `afl-fuzz` binaries require Python custom-mutator support. If the local
NoGen binary is missing, the launcher runs `make afl-fuzz`. The normal version
requires native G2FUZZ to be built first and reports a missing binary before
requesting model generation. Use `--g2fuzz-dir /path/to/G2FUZZ` or `G2FUZZ_DIR`
to select another complete native build. The default is this project's
`G2FUZZ/` directory.

Targets can be instrumented with this project's `afl-clang-fast` or
`afl-clang-fast++`. The curated AFL++ tree at the project root does not include
all upstream optional emulation backends; use its supported default build target.

## Model Configuration

Native G2FUZZ reads model settings from `model_setting.json` and credentials from
`openai_key.txt` in its current working directory. The complete launcher creates
configuration copies under `RUN_DIR/g2fuzz_work/`, maps the selected program to
the format specified by `--format`, and sets the credential file permissions to
`0600`.

```bash
export OPENAI_API_KEY='your-api-key'
# Set this for an OpenAI-compatible provider; omit it for the OpenAI service
export OPENAI_BASE_URL='https://your-provider.example/v1'
```

`AFL_LLM_API_KEY` and `AFL_LLM_BASE_URL` are also supported. Select a model with
`--model`; otherwise, the launcher uses `AFL_LLM_MODEL`, then the first model in
the native `model_setting.json`. The selected model and endpoint are passed to
all three generation stages. If no endpoint is configured, all three stages use
`https://api.openai.com/v1`.

To supply custom native configuration files, use `--g2fuzz-config-dir DIR`.
The directory must contain `model_setting.json` and `program_to_format.json`
and may also contain `openai_key.txt`. Credential environment variables take
precedence over the credential file. No changes to the configuration inside
`G2FUZZ/` are required.

Native generators may need additional format-specific dependencies. Prepare
them according to the native G2FUZZ workflow.

## Run the Complete Pipeline

The interface is:

```text
./run.sh [OPTIONS] --program NAME --format FORMAT INPUT_DIR RUN_DIR -- TARGET [TARGET_ARGS...]
```

`INPUT_DIR` contains existing user seeds and may be empty. After native generation
succeeds, nonempty user seeds and native seeds are merged into `RUN_DIR/seeds/`.
Native seed filenames are preserved to maintain their association with native
generators. By default, the first nonempty native seed in sorted order is used
to synthesize the initial template. Override it with
`--template-seed /absolute/path/to/seed`.

Normal version:

```bash
mkdir -p seeds
./run.sh --program objdump --format elf --model your-model \
  --expand-count 5 \
  ./seeds ./runs/objdump-normal -- /absolute/path/to/objdump.afl -d @@
```

NoGen version:

```bash
./run.sh --nogen --program objdump --format elf --model your-model \
  --expand-count 5 \
  ./seeds ./runs/objdump-nogen -- /absolute/path/to/objdump.afl -d @@
```

The normal version passes the native `-k G2FUZZ_DIR` option and retains native
runtime generation. NoGen uses `afl-fuzz` at the project root without `-k`.
Both versions load `MutatorMin`, set `AFL_LLM_TEMPLATE_POOL=1` and
`AFL_LLM_TEMPLATE_INITIAL_ONLY=0`, and schedule executors from both the initial
template and the expanded pool. `AFL_LLM_SEED_GEN` is fixed to `0` in both modes;
native runtime generation is provided by the normal mode's G2FUZZ binary.

The fuzzer starts in `RUN_DIR/g2fuzz_work/` to satisfy the unmodified native
code's relative configuration paths. The target executable is resolved before
changing directories; use absolute paths for any other files or directories in
the target arguments. Native runtime generation constructs an unquoted shell
command, so the normal version requires G2FUZZ source and output paths without
spaces or shell metacharacters.

## Prepare and Run Separately

Generate all artifacts without starting the fuzzer:

```bash
./run.sh --prepare-only --program objdump --format elf --model your-model \
  --expand-count 5 \
  ./seeds ./runs/objdump-prepared -- /absolute/path/to/objdump.afl -d @@
```

Then explicitly reuse the successfully prepared artifacts, for example with NoGen:

```bash
./run.sh --reuse-prepared --nogen --program objdump --format elf \
  ./seeds ./runs/objdump-prepared -- /absolute/path/to/objdump.afl -d @@
```

Reuse loads the templates, seeds, native directory, and configuration recorded
in `pipeline.json` without making new model requests. The program and format
must match, and the templates, expanded code, and seeds must exist. By default,
the complete pipeline requires a new or empty run directory to avoid
overwriting previous artifacts. If any generation stage fails, fuzzing does
not start. `--reuse-prepared` starts a prepared run; it does not automatically
resume an existing AFL fuzzing session.

`run_fuzz.sh` remains available as a lower-level launcher. It requires an initial
template path, an executor pool directory, and a native working directory to
be configured. Usually, `run.sh --reuse-prepared` is the simpler interface.

## Manual Step-by-Step Execution

The following commands invoke the native scripts, template tools, and fuzzer
individually without using `run.sh`. Complete the build and dependency setup
above, then run the steps in order in the same Bash session. The examples use
`objdump` and `elf`; when changing targets, update the program name, format,
target executable, and target arguments together.

### 1. Set Paths, Model Settings, and Native Configuration Copies

Start in the F2Mut project root and replace the model, API key, and target path.
`RUN_DIR` must be a new directory that does not already exist. For the normal
version, source and output paths must not contain spaces or shell metacharacters.

```bash
set -euo pipefail

export F2MUT_ROOT="$(pwd -P)"
export G2FUZZ_DIR="$F2MUT_ROOT/G2FUZZ"
export RUN_DIR="$F2MUT_ROOT/runs/objdump-manual-normal"
export INPUT_DIR="$F2MUT_ROOT/seeds"
export TARGET_BIN='/absolute/path/to/objdump.afl'
export PROGRAM='objdump'
export FORMAT='elf'
export MODEL='your-model'

export OPENAI_API_KEY='your-api-key'
export OPENAI_BASE_URL="${OPENAI_BASE_URL:-https://api.openai.com/v1}"
export PYTHONPATH="$F2MUT_ROOT${PYTHONPATH:+:$PYTHONPATH}"
export PYTHONDONTWRITEBYTECODE=1

test ! -e "$RUN_DIR"
test -x "$TARGET_BIN"
mkdir -p "$INPUT_DIR" "$RUN_DIR/g2fuzz_work" "$RUN_DIR/fuzzer/default" \
  "$RUN_DIR/initial_template" "$RUN_DIR/generated_format_executors" \
  "$RUN_DIR/seeds"

python - <<'PY'
import json
import os
from pathlib import Path

source = Path(os.environ['G2FUZZ_DIR'])
work = Path(os.environ['RUN_DIR']) / 'g2fuzz_work'
models = json.loads((source / 'model_setting.json').read_text())
models['model'] = [os.environ['MODEL']]
programs = json.loads((source / 'program_to_format.json').read_text())
programs[os.environ['PROGRAM']] = [os.environ['FORMAT']]
(work / 'model_setting.json').write_text(json.dumps(models, indent=2) + '\n')
(work / 'program_to_format.json').write_text(json.dumps(programs, indent=2) + '\n')
fd = os.open(work / 'openai_key.txt', os.O_WRONLY | os.O_CREAT | os.O_TRUNC, 0o600)
with os.fdopen(fd, 'w') as output:
    os.fchmod(output.fileno(), 0o600)
    output.write(os.environ['OPENAI_API_KEY'].strip() + '\n')
PY

cd "$RUN_DIR/g2fuzz_work"
```

Run the remaining commands from this working directory, using absolute paths for
sources and artifacts. Native code reads its configuration and credentials
here, leaving the original files in `G2FUZZ/` unchanged. `python` must resolve
to the interpreter with the required dependencies; native generators also use
it when executing generated code.

### 2. Generate Seeds and Initial Features with Native program_gen.py

```bash
python "$G2FUZZ_DIR/program_gen.py" \
  --output "$RUN_DIR/fuzzer" \
  --program "$PROGRAM"
```

Check for `gen_seeds/`, `generators/`, `feature_pool.json`, and
`feature_programs.json` under `RUN_DIR/fuzzer/default/`. The next snippet merges
nonempty native seeds with existing user seeds and selects the sample for
initial template synthesis. The user seed directory may be empty.

```bash
python - <<'PY'
import json
import os
from pathlib import Path
import shutil

run = Path(os.environ['RUN_DIR'])
state = run / 'fuzzer' / 'default'
features = json.loads((state / 'feature_pool.json').read_text())
if not isinstance(features, dict) or not features:
    raise SystemExit('Native feature pool is empty; check the program_gen.py output')
native_seeds = sorted(p for p in (state / 'gen_seeds').rglob('*')
                      if p.is_file() and p.stat().st_size)
if not native_seeds:
    raise SystemExit('No nonempty seeds were found in the native generation directory')
corpus = run / 'seeds'
for source in native_seeds:
    destination = corpus / source.name
    if destination.exists():
        raise SystemExit('Seed filename collision: ' + str(destination))
    shutil.copy2(source, destination)
user_seeds = sorted(p for p in Path(os.environ['INPUT_DIR']).rglob('*')
                    if p.is_file() and p.stat().st_size)
for index, source in enumerate(user_seeds):
    destination = corpus / f'user-{index:06d}{source.suffix}'
    if destination.exists():
        raise SystemExit('Seed filename collision: ' + str(destination))
    shutil.copy2(source, destination)
(run / 'template_seed.txt').write_text(str(native_seeds[0]) + '\n')
print('Initial template seed:', native_seeds[0])
print('Merged corpus directory:', corpus)
PY

TEMPLATE_SEED="$(cat "$RUN_DIR/template_seed.txt")"
export TEMPLATE_SEED
```

Native seeds keep their original filenames so G2FUZZ can associate them with
their generators at runtime. To synthesize the initial template from another
sample, set `TEMPLATE_SEED=/absolute/path/to/seed` before the next step.

### 3. Synthesize the Initial Template with template_seed_prompt_generator.py

```bash
python "$F2MUT_ROOT/template_seed_prompt_generator.py" \
  "$FORMAT" "$TEMPLATE_SEED" \
  --call-llm \
  --model "$MODEL" \
  --base-url "$OPENAI_BASE_URL" \
  --api-key-env OPENAI_API_KEY \
  --target-program "$PROGRAM" \
  --target-args='-d @@' \
  --tool-output "g2fuzz_features=$RUN_DIR/fuzzer/default/feature_pool.json" \
  --output-code "$RUN_DIR/initial_template/executor.py" \
  --output-json "$RUN_DIR/initial_template/executor.json" \
  --summary-json "$RUN_DIR/initial_template/seed_summary.json"
```

`--target-args` must match the arguments used in the final target command. This
step reads the selected seed and native initial features, validates the generated
executor, and saves it as `initial_template/executor.py`.

### 4. Expand Loadable Executors with template_expander.py

```bash
python "$F2MUT_ROOT/template_expander.py" \
  "$RUN_DIR/initial_template/executor.py" \
  --sample "$TEMPLATE_SEED" \
  --feature-pool "$RUN_DIR/fuzzer/default/feature_pool.json" \
  --model "$MODEL" \
  --url "$OPENAI_BASE_URL" \
  --style mixed \
  --count 5 \
  --output-dir "$RUN_DIR/generated_format_executors"
```

Expanded executors are saved in `generated_format_executors/`. `MutatorMin`
loads the `.py` files, and the accompanying `.json` files record the generated
content. Start fuzzing only after this command succeeds and the directory
contains nonempty `.py` files.

### 5. Configure the MutatorMin Template and Executor Pool

```bash
export AFL_PYTHON_MODULE=MutatorMin
export AFL_IGNORE_UNKNOWN_ENVS=1
export AFL_LLM_TEMPLATE_MODE=1
export AFL_LLM_TEMPLATE_POOL=1
export AFL_LLM_TEMPLATE_INITIAL_ONLY=0
export AFL_LLM_FALLBACK_TEMPLATE_EXECUTOR="$RUN_DIR/initial_template/executor.py"
export AFL_LLM_FORMAT_EXECUTOR_DIR="$RUN_DIR/generated_format_executors"
export AFL_LLM_MUTATORS_DIR="$RUN_DIR/runtime_state"
export AFL_LLM_AFL_OUT="$RUN_DIR/fuzzer/default"
export AFL_LLM_G2FUZZ_SOURCE_DIR="$G2FUZZ_DIR"
export AFL_LLM_G2FUZZ_WORK_DIR="$RUN_DIR/g2fuzz_work"
export AFL_LLM_SEED_GEN=0
export AFL_LLM_BOTTLENECK_EXPANSION=0
unset AFL_LLM_API_KEY

cd "$RUN_DIR/g2fuzz_work"
```

Native G2FUZZ echoes unrecognized `AFL_` variables in its startup log, so unset
`AFL_LLM_API_KEY` before starting it. Native runtime generation still reads the
key from `openai_key.txt` in the working directory. The two template tools have
already completed generation using `OPENAI_API_KEY`.

### 6. Start the Normal or NoGen Version

The normal version uses the native G2FUZZ binary, with `-k` pointing to its
original script directory. Its output directory is the same as in step 2, so
the existing generator and feature state remains available:

```bash
"$G2FUZZ_DIR/afl-fuzz" \
  -i "$RUN_DIR/seeds" \
  -o "$RUN_DIR/fuzzer" \
  -k "$G2FUZZ_DIR" \
  -- "$TARGET_BIN" -d @@
```

NoGen uses the binary built from this project's sources, with the same initial
corpus and template pool:

```bash
"$F2MUT_ROOT/afl-fuzz" \
  -i "$RUN_DIR/seeds" \
  -o "$RUN_DIR/fuzzer" \
  -- "$TARGET_BIN" -d @@
```

Choose one of these two launch commands. To run both versions separately, use
different `RUN_DIR` values in step 1 and prepare artifacts for each run. Do not
start the other version directly in an AFL output directory that has already
been used. Use absolute paths for any other files in the target arguments.

After steps 1 through 5, the lower-level launcher can also check paths and select
the appropriate binary:

```bash
# Normal version
"$F2MUT_ROOT/run_fuzz.sh" "$RUN_DIR/seeds" "$RUN_DIR/fuzzer" -- "$TARGET_BIN" -d @@

# Or select NoGen
"$F2MUT_ROOT/run_fuzz.sh" --nogen "$RUN_DIR/seeds" "$RUN_DIR/fuzzer" -- "$TARGET_BIN" -d @@
```

The fully manual workflow does not create `pipeline.json`. Continue using the
direct commands above or `run_fuzz.sh` for manually prepared artifacts.
`run.sh --reuse-prepared` applies to artifacts successfully prepared and recorded
by the complete launcher.

## Run Artifacts

```text
RUN_DIR/
├── pipeline.json                   # Successful preparation record, without credentials
├── g2fuzz_work/
│   ├── model_setting.json
│   ├── program_to_format.json
│   └── openai_key.txt               # Runtime credential copy, mode 0600
├── seeds/                          # Merged AFL initial corpus
├── initial_template/
│   ├── executor.py
│   ├── executor.json
│   └── seed_summary.json            # Includes native initial feature context
├── generated_format_executors/      # Expanded .py/.json files for the scheduler
├── runtime_state/                  # Scheduling and feedback state
└── fuzzer/
    └── default/
        ├── gen_seeds/
        ├── generators/
        ├── feature_pool.json
        ├── feature_programs.json
        ├── queue/                  # Created after the fuzzer starts
        ├── crashes/
        └── fuzzer_stats
```

`template_expander.py` reads the native string mapping in `feature_pool.json`
directly and also accepts the existing structured feature-pool format.
`--expand-style` defaults to `mixed`, and `--expand-count` defaults to `1`.
Use each template tool's `--help` option for its other standalone arguments.

## Executor Scheduling

Select a strategy with `AFL_LLM_TEMPLATE_POOL_SCHEDULE`:

| Value | Selection weight |
| --- | --- |
| `random` | Uniform random selection across eligible executors |
| `coverage_per_call` | `max(C / N, 1e-6)`; untried executors are selected first |
| `coverage` | `1 + C`; untried executors are selected first |

`C` is the cumulative number of AFL queue discoveries marked `+cov`, and `N` is
the number of Python `fuzz()` calls. Weighted strategies explore uniformly with
probability `0.15` by default; adjust it with `AFL_LLM_TEMPLATE_POOL_EXPLORE`.
Each stage retains one executor for 64 calls. Set
`AFL_LLM_TEMPLATE_FEEDBACK_WRITES=1` or `AFL_LLM_RUNTIME_STATUS_WRITES=1` to
persist feedback or runtime status, respectively.

## Validation

```bash
python3 -B -m unittest discover -s tests -v
bash -n run.sh run_fuzz.sh
```

Offline integration tests run the real native `program_gen.py` and both template
CLIs, supplying explicit test responses only at the model SDK boundary. Real
`MutatorMin` callbacks then load and execute the generated code. Binary-selection
checks use stand-in programs without external model calls or formal fuzzing
experiments.
